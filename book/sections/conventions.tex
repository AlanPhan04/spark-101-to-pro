\chapter{Conventions Used in This Book}
\label{ch:conventions}

The following typographic conventions are used in this book.

\begin{description}[leftmargin=0pt, labelindent=0pt, itemsep=4pt]
  \item[\emph{Italic}] marks a new term where it is defined, once, at its first
  use. After that the term is used plainly.
  \item[\texttt{Monospace}] marks code, SQL keywords, table and column names, file
  names, and the output of commands. Configuration keys in running text look like
  \conf{spark.memory.fraction}, and may break at the dots.
  \item[\textbf{Bold}] marks the first words of a run-in heading and, in tables, the
  column names.
\end{description}

\section*{Callouts}

Four boxes mark text that is not part of the main line of the argument. At most
one appears on a typical page.

\begin{note}
Marks a version gotcha, a clarification, or a pointer to a later chapter.
\end{note}

\begin{warning}
Marks a default or a pattern that silently costs money, correctness, or data.
\end{warning}

\begin{tip}
Marks a diagnostic shortcut: a UI panel to check, a one-line command.
\end{tip}

\begin{analogy}
Marks a plain-language comparison used to build intuition for a mechanism. It
never replaces the mechanism, and it is pushed only as far as it stays accurate.
Skip it if it does not click for you; the surrounding prose never depends on it.
\end{analogy}

\section*{Listings}

Code and output appear in listings with a language tag: \texttt{sql}, \texttt{scala},
or \texttt{text} for plans, UI excerpts, and shell output. A listing that produces
output is followed by that output, labelled, so you can compare what you expect with
what happened.

Query plans are lightly trimmed. An ellipsis comment such as
\texttt{-- ... 3 Filter nodes elided} marks a cut. Wide plans use smaller type and
wrap long lines rather than running off the page.

\section*{How sure the book is}

Every behavioral claim is written against one reference stack
(\Cref{app:refenv}): Spark 3.5.2 and Iceberg format version 2. A behavior is stated
as fact only if it holds there. When behavior changed across versions, a Note names
the version. Defaults are quoted as of Spark 3.5.2.

Because statements deserve different amounts of trust, the book labels three kinds:

\begin{description}[leftmargin=0pt, labelindent=0pt, itemsep=4pt]
  \item[Measured.] Produced by a lab script and shown with its output. These are
  the numbers and plans in listings and figures. They are reproducible on the lab
  setup; on your cluster, expect the same mechanism and a different magnitude.
  \item[Derived.] Follows from a formula or from the source code of Spark or
  Iceberg, and is checked against a measurement where one exists.
  \item[Claimed.] Stated from documentation or experience, but not tested here.
  These are marked ``claim --- not tested'' or ``claim --- verify on your
  cluster.''
\end{description}

A number such as a threshold, a size, or a speedup always comes with a source, or
with ``measured'' and the environment that measured it.

\section*{Terminology}

Where two names circulate for the same thing, the book picks one:

\begin{itemize}
  \item \emph{stage boundary}, not ``shuffle boundary'';
  \item \emph{unified memory}, not ``managed memory'';
  \item \emph{manifest list}, \emph{manifest}, and \emph{data file}, exactly as the
  Iceberg specification spells them;
  \item an \emph{executor} is a process, a \emph{task} is a thread, and a
  \emph{slot} is one core.
\end{itemize}

The glossary (\Cref{app:glossary}) lists every term with the chapter that defines
it.

\section*{Figures and cross-references}

Figures are vector graphics, so they stay sharp at any zoom, and they share one
color palette. A figure that shows a measured result says so in its caption.
Cross-references are links, and a reference to a chapter, section, figure, or
listing is always followed by its number.

\section*{The running example}

The \texttt{orders} table and its star schema are introduced in \Cref{app:refenv}
and reused in every chapter. Table and column names are typeset in
\texttt{monospace}.
