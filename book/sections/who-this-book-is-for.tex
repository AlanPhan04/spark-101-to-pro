\chapter{Who This Book Is For}
\label{ch:who-for}

This book is for you if you write Python and SQL, you want to work with large
data, and nobody has yet shown you what happens between pressing \emph{run} and
seeing the result. You do not need to have used Spark, run a cluster, or read a
query plan. You do need to be curious about \emph{why} a query is fast or slow,
because that is the question every chapter answers.

You might recognize yourself in one of these:

\begin{itemize}
  \item You are a data engineer, analytics engineer, or data analyst who has been
  told to ``move this pipeline to Spark,'' and you want a mental model before you
  start changing settings.
  \item You have a query that runs fine on a sample and takes an hour on the real
  table, and nobody can tell you why.
  \item A colleague said ``check the shuffle'' or ``that table is Iceberg, so
  it'll prune,'' and you nodded without being sure what either meant.
  \item You have copied \texttt{spark.sql.*} settings from a forum and cannot say
  what any of them does.
  \item You work with Spark already, but the optimizer and the table format still
  feel like black boxes.
\end{itemize}

If one of these is you, the book is aimed at the gap between where you are and
where \Cref{tab:who-levels} says you can be.

\section*{What you should already know}

You need three things:

\begin{itemize}
  \item \textbf{Python basics}: functions, lists, dictionaries, and running a script
  from a terminal.
  \item \textbf{SQL basics}: \texttt{SELECT}, \texttt{WHERE}, \texttt{GROUP BY}, and
  \texttt{JOIN}. Window functions and subqueries appear later and are explained
  where they appear.
  \item \textbf{A terminal}: enough to run a command and read its output. The
  lab runs in Docker, so installing it helps; the repository's \texttt{lab/README}
  lists the commands.
\end{itemize}

You do \emph{not} need Hadoop, Java, Scala, or a cluster. A few examples in
Part~V use Scala where SQL cannot express the idea; they are short and explained
line by line. Kubernetes is the book's reference deployment, so the word appears in
Part~I. You never have to operate it to follow along.

\section*{What this book does not cover}

To keep the focus on query performance on a lakehouse, the book leaves out:

\begin{itemize}
  \item Scala or Java as languages;
  \item MLlib, GraphX, and machine-learning workloads;
  \item provisioning a cluster, or administering Kubernetes beyond what the
  executor sizing chapters require;
  \item the pandas API on Spark;
  \item Delta Lake and Apache Hudi, except where a comparison with Iceberg
  clarifies a design choice.
\end{itemize}

\section*{If you are somewhere else on the path}

\textbf{If Spark is entirely new to you,} read straight through and let
\Cref{ch:shape} give you the vocabulary. It is the gentlest chapter, but it moves
fast. A companion that teaches the DataFrame API line by line, such as
\emph{Learning Spark} \cite{DamjiEtAl2020}, makes a good second book to keep open
beside this one. \Cref{ch:how-to-use} marks which sections to skim on a first read.

\textbf{If you already run Spark jobs,} start with the symptom path in
\Cref{ch:how-to-use}, and treat the rest as the mechanism behind what you see.

\textbf{If you administer the cluster rather than query it,} Parts~I and~IV will
serve you, and Part~III will explain what your users' tables are doing to your
object store.

\textbf{If you already read query plans for a living,} the Iceberg chapters
(Part~III) and the measured experiments are where this book is most likely to tell
you something new.
